# Финальное задание: API -> Data Lake -> витрина -> Airflow

Нужно сделать небольшой end-to-end data engineering project: забрать данные из публичного API, сохранить raw-слой, обработать данные, загрузить витрину в аналитическую БД и оркестрировать пайплайн через Airflow.

## 1. Выбрать публичное API

Выберите любое публичное API без сложной авторизации.

Примеры:

- Open-Meteo: `https://open-meteo.com/`
- SpaceX API: `https://api.spacexdata.com/`
- JSONPlaceholder: `https://jsonplaceholder.typicode.com/`
- CoinGecko API: `https://api.coingecko.com/api/v3/`
- Open Library API: `https://openlibrary.org/developers/api`

Можно выбрать другой источник, если данные можно получить обычным HTTP-запросом.

Требования к данным:

- минимум две сущности, которые можно связать между собой;
- или одна сущность с вложенной структурой, которую можно развернуть в несколько таблиц;
- данные должны позволять сделать хотя бы одну агрегацию.

Примеры:

- города и погода по дням;
- книги и авторы;
- криптовалюты и цены;
- пользователи и посты;
- запуски SpaceX и ракеты.

## 2. Забрать данные из API

Напишите Python-код или Airflow task, который получает данные из API.

Raw-ответы сохраните как JSON.

Рекомендуемая структура raw-слоя:

```text
raw/<source_name>/<entity>/dt=YYYY-MM-DD/*.json
```

Пример:

```text
raw/open_meteo/weather/dt=2026-07-01/weather_moscow.json
raw/open_meteo/cities/dt=2026-07-01/cities.json
```

## 3. Сохранить raw-данные

Выберите один вариант хранения raw-слоя:

- S3/MinIO;
- HDFS/Hadoop.

Raw-слой должен хранить исходные JSON-ответы или JSON Lines без потери полей.

## 4. Обработать данные

Сделайте обработку данных (желательно используя Spark):

- прочитайте raw JSON;
- разберите вложенные поля;
- приведите типы данных;
- уберите очевидные дубли;
- обработайте пропуски там, где это необходимо;
- сформируйте минимум две таблицы в `stg` или `ods`.

Пример слоёв:

```text
stg.<source_name>_<entity>
ods.<source_name>_<entity>
mart.<source_name>_<mart_name>
```

## 5. Сделать витрину

Создайте минимум одну витрину в слое `mart`.

Витрина должна содержать:

- join между таблицами или разбор вложенной структуры;
- агрегацию;
- понятные бизнес-поля.

Примеры витрин:

- средняя температура по городу и дню;
- топ валют по изменению цены;
- количество книг по авторам;
- статистика постов по пользователям;
- количество запусков SpaceX по ракетам и годам.

## 6. Загрузить витрину в аналитическую БД

Выберите одну целевую систему:

- ClickHouse;
- Greenplum.

Для ClickHouse создайте таблицу в database `mart`.

Для Greenplum создайте таблицу в schema `mart`.

Пример имени:

```text
mart.<source_name>_daily_stats
```

## 7. Оркестрировать через Airflow

Соберите Airflow DAG, который запускает весь пайплайн.

Минимальная цепочка task-ов:

```text
extract_api
>> load_raw
>> transform
>> load_mart
>> check_result
```

`check_result` должен выполнить проверочный SQL-запрос или вывести его в лог.

DAG:

```text
schedule=None
catchup=False
```

## 8. Что приложить в ответ

Приложите:

1. описание выбранного API и ссылку на документацию;
2. схему raw/stg/ods/mart слоёв;
3. код Airflow DAG;
4. код Python-скриптов или SQL-запросов;
5. SQL для создания целевых таблиц;
6. скриншот успешного запуска DAG;
7. результат проверочного SQL-запроса из витрины;
8. короткое описание, почему выбрали ClickHouse или Greenplum.

## 9. Дополнительно, по желанию

Можно улучшить проект:

- сделать DAG идемпотентным, чтобы повторный запуск не создавал дубли;
- добавить retry для запросов к API;
- добавить data quality checks;
- добавить партиционирование raw-слоя по дате;
- добавить несколько витрин;
- добавить описание ограничений выбранного API.
